# 1.3.7 场景壁纸切换修复

日期：2026-10-12。保留原有未提交修改，修复前快照位于 `verification/switch-before-20261012-095138/`，包括源文件、原有安装入口/后端和配置备份。备份目录仅本机保存，不进入发布包。

## 已确认原因

本机 `config.yaml` 为 `plugins.enabled: []`，同时 `plugins.disabled` 包含 `hermes-skins`。Hermes 官方插件列表也显示该后端 disabled。2026-10-10 与 2026-10-11 的宿主日志反复记录 `POST /api/plugins/hermes-skins/scene/prepare` 返回 `404 Plugin not found`；本轮真实健康接口也复现相同错误。

图片/视频由桌面播放器直接加载；已保存场景也可以直接读取已解包清单。因此它们仍能工作，不代表新场景的后端解包接口可用。当前选用的视频“鲸落”能够播放，但新场景无法完成准备。

此前 1.3.6 验证覆盖了当前缓存场景播放、材质性能及资源释放，没有覆盖“后端禁用时选择新场景”的完整路径。本轮补上该检查。没有证据表明参数合并或纹理复用本身导致此次接口 404。

## 修复

- 已通过 Hermes 官方 `/api/dashboard/agent-plugins/hermes-skins/enable` 恢复启用。随后通过官方 CLI 完整部署 **1.3.7**；不再使用 `--no-enable` 作为本轮交付方式。当前壁纸、模式、库目录及选择记录保留。
- 场景选择报 404 时，壁纸页显示明确的后端诊断并提供“启用场景后端”。该按钮使用官方插件管理事务，随后检查 `/scene/health`；路由可用时重试刚才选择的场景。
- `gateway_reloaded: true` / `restart_required: false` 仅代表 agent 插件处理器的激活，不能证明 dashboard 插件路由已经挂载。健康接口仍 404 时，页面明确提示待当前任务结束后重启 Hermes；保持原有壁纸，不盲目提交失败的选择。
- 安装器将实际目标 `HERMES_HOME` 传给 CLI。真实 CLI 启用失败会报错，不再通过直接写 `plugins.enabled` 掩盖失败；这种写法既不能清除显式 disabled，也不能发布官方 PM 准入状态。CLI 不存在时提示从插件管理器启用。
